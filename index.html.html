📖 O que é Git e GitHub?
Git — O Controle de Versão
Git é um sistema que registra todas as alterações feitas em seus arquivos ao longo do tempo. Com ele, você consegue voltar no passado, comparar versões diferentes e trabalhar em equipe sem bagunça.
Analogia: Imagina que seu código é um livro que você está escrevendo. O Git é como tirar fotos de cada página em momentos diferentes. Se você errar alguma coisa, é só voltar à foto anterior!
GitHub — A Nuvem do Código
GitHub é uma plataforma online onde você guarda seus repositórios Git. É como um Google Drive, mas especialmente feito para código. Você pode compartilhar seus projetos, colaborar com outros devs e montar seu portfólio.
Analogia: O Git é a câmera fotográfica, e o GitHub é o álbum online onde você guarda e compartilha essas fotos com todo mundo.
Repositório (repo)
É a pasta do seu projeto que o Git fica monitorando. Dentro dela, o Git cria uma pasta oculta chamada .git que guarda todo o histórico.
Analogia: O repositório é a pasta de um projeto escolar. Tudo que está dentro dela o Git acompanha. A pasta .git é o diário secreto onde o Git anota tudo.
Commit — O Ponto de Salvamento
Um commit é um ponto de salvamento do seu trabalho. Cada commit tem uma mensagem que explica o que foi feito e fica registrado no histórico para sempre.
Analogia: Sabe quando você joga um videogame e salva numa fase especial? O commit é esse salvamento. Se você morrer depois (errar o código), é só voltar para esse ponto.
Branch — A Linha do Tempo Paralela
Uma branch é uma linha de desenvolvimento separada. Você pode criar uma branch para testar uma nova funcionalidade sem afetar o código principal, e depois juntar tudo com um merge.
Analogia: Imagine que você está escrevendo um trabalho e quer testar um trecho diferente sem perder o que já escreveu. Você tira uma xerox (cria uma branch), experimenta nela, e se ficar bom, cola no original (merge).
💻 Comandos Essenciais
🚀 Iniciar
Configurar Git
git config --global user.name "Seu Nome"copiar git config --global user.email "email@x.com"copiar git initcopiar
Configure seu nome e email antes de usar o Git. O git init cria um novo repositório na pasta atual.
📋 Verificar
Ver o que está acontecendo
git statuscopiar git logcopiar git log --onelinecopiar
Use sempre o git status para ver o estado atual. O --oneline mostra o histórico de forma resumida.
➕ Adicionar
Preparar arquivos para commit
git add nome-do-arquivo.txtcopiar git add .copiar
O git add . adiciona todos os arquivos modificados de uma vez. Cuidado: revise antes!
💾 Salvar
Criar um commit
git commit -m "sua mensagem aqui"copiar
A mensagem do commit deve ser clara e no imperativo: "Adiciona botão de login" em vez de "adicionei" ou "botão".
🌐 GitHub
Conectar com repositório remoto
git remote add origin URLcopiar git push -u origin maincopiar git pullcopiar
O push envia para o GitHub. O pull traz as novidades do GitHub para sua máquina.
🌿 Branches
Trabalhar em paralelo
git branch nome-da-branchcopiar git checkout nome-da-branchcopiar git checkout -b nova-branchcopiar
O -b cria e já troca para a nova branch de uma vez só.
💡
Dica de ouro: Sempre rode git status antes e depois de qualquer operação. Ele é seu melhor amigo para entender o que o Git está vendo!

01
Meu Primeiro Repositório
Fácil git init git add git commit
▼
Seu objetivo é criar um repositório Git local do zero, adicionar um arquivo e registrar seu primeiro commit. Isso é o "Olá, Mundo!" do Git!
  1. Crie uma pasta chamada meu-primeiro-repo em qualquer lugar do seu computador
  2. Abra o terminal e navegue até ela com cd meu-primeiro-repo
  3. Execute git init para transformá-la em um repositório
  4. Crie um arquivo chamado README.md com uma apresentação sua
  5. Execute git status e observe o que o Git diz
  6. Execute git add README.md
  7. Execute git commit -m "Adiciona apresentação no README"
  8. Execute git log para ver seu commit no histórico!
✅ Objetivo alcançado quando: O git log mostrar seu commit com a mensagem "Adiciona apresentação no README".
02
Subindo para o GitHub
Fácil remote git push
▼
Agora vamos conectar seu repositório local com o GitHub e enviar seu código para a nuvem pela primeira vez!
  1. Crie uma conta no github.com se ainda não tiver
  2. Crie um novo repositório no GitHub chamado meu-primeiro-repo (sem inicializar com README)
  3. Copie a URL do repositório (termina em .git)
  4. No terminal, execute git remote add origin SUA_URL_AQUI
  5. Execute git push -u origin main
  6. Atualize a página do GitHub e veja seu arquivo lá!
✅ Objetivo alcançado quando: Seu README.md aparecer no repositório do GitHub com sua apresentação.
03
Histórico de Versões
Fácil múltiplos commits git log
▼
Vamos criar um pequeno portfólio de projetos escolares e praticar a criação de múltiplos commits significativos.
  1. No seu repositório, crie um arquivo projetos.md
  2. Adicione o título "# Meus Projetos" e commit: "Cria arquivo de projetos"
  3. Adicione o nome de 2 projetos que você já fez (ou quer fazer) e commit: "Adiciona lista de projetos"
  4. Adicione uma descrição para cada projeto e commit: "Adiciona descrições dos projetos"
  5. Execute git log --oneline para ver o histórico resumido
  6. Execute git push para atualizar o GitHub
✅ Objetivo alcançado quando: O git log --oneline mostrar pelo menos 4 commits (o README + 3 novos).
04
Explorando Branches
Médio branch merge
▼
Hora de trabalhar com branches! Você vai criar uma branch para desenvolver uma nova seção do portfólio sem bagunçar o código principal.
  1. Execute git checkout -b feature/habilidades para criar e entrar na nova branch
  2. Crie um arquivo habilidades.md com suas habilidades em tecnologia
  3. Faça commit: "Adiciona arquivo de habilidades"
  4. Execute git checkout main — note que o arquivo sumiu! Está seguro na outra branch
  5. Execute git merge feature/habilidades para trazer de volta
  6. O arquivo apareceu! Faça git push
✅ Objetivo alcançado quando: O arquivo habilidades.md aparecer na branch main após o merge.
05
Clone & Pull Request
Médio clone pull request
▼
Vamos simular o trabalho colaborativo! Você vai clonar o repositório de um colega, fazer uma contribuição e abrir um Pull Request — o coração do trabalho em equipe no GitHub.
  1. Combine com um colega de turma para trocarem os links dos repos do GitHub
  2. Execute git clone URL_DO_REPO_DO_COLEGA em uma pasta diferente
  3. Entre na pasta clonada e crie uma branch: git checkout -b contribuicao/seu-nome
  4. Faça alguma melhoria: corrija um erro, adicione informação, melhore o README
  5. Commit e git push origin contribuicao/seu-nome
  6. No GitHub, abra um Pull Request comparando sua branch com a main do colega
  7. Escreva uma descrição explicando o que você mudou e por quê
✅ Objetivo alcançado quando: Seu Pull Request aparecer aberto no repositório do colega, aguardando revisão.
06
Portfólio no GitHub Pages
Avançado GitHub Pages deploy
▼
O desafio final! Você vai publicar uma página HTML na internet de graça usando o GitHub Pages. Qualquer pessoa no mundo poderá ver seu portfólio.
  1. Crie um novo repositório no GitHub com o nome exato: seu-usuario.github.io
  2. Clone ele na sua máquina com git clone URL
  3. Crie um arquivo index.html com uma página simples de portfólio
  4. Faça git add ., git commit -m "Cria portfólio inicial" e git push
  5. Aguarde 1–2 minutos e acesse https://seu-usuario.github.io no navegador
  6. Continue melhorando e commitando — cada push atualiza seu site automaticamente!
✅ Objetivo alcançado quando: Sua página aparecer online em seu-usuario.github.io e você conseguir compartilhar o link!
📚 Glossário Git
repository
A pasta do projeto monitorada pelo Git. Contém todos os arquivos e o histórico completo de mudanças.
commit
Um ponto de salvamento com mensagem descritiva. Cada commit tem um código único chamado hash.
branch
Uma linha paralela de desenvolvimento. A branch principal geralmente se chama main.
merge
A união de duas branches. O Git tenta combinar as mudanças automaticamente.
clone
Baixar uma cópia completa de um repositório remoto, incluindo todo o histórico.
push
Enviar commits locais para o repositório remoto (GitHub). "Empurrar" para cima.
pull
Baixar e aplicar commits do repositório remoto no local. "Puxar" de cima.
staging area
Área intermediária onde você prepara as mudanças antes de commitar. O git add move arquivos para cá.
remote
Versão do repositório hospedada em servidor externo, como o GitHub. O nome padrão é origin.
pull request
Solicitação para que o dono de um repositório aceite suas mudanças. O coração da colaboração no GitHub.
.gitignore
Arquivo que diz ao Git quais arquivos ignorar. Útil para senhas, dependências e arquivos temporários.
conflict
Quando duas branches modificam a mesma parte de um arquivo. O Git pede que você resolva manualmente.
